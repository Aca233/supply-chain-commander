# Responsive UI Adaptation Design

## Summary

目标是让主游戏页面在较小桌面窗口、平板和手机宽度下都保持“功能可见、可操作、不会被固定侧栏挤没”的状态，同时尽量保持当前视觉语言和信息架构。

这次改造采用“断点自适应重排”方案，而不是简单缩小字体或做整站紧凑模式。核心思路是：当窗口宽度不足时，优先保留主任务区域，把左栏、右栏、详情面板、浮动队列等次级区域切换为抽屉、覆盖层或显式按钮入口。

## Scope

### In Scope

- `src/ui/pages/Dashboard.tsx`
- `src/ui/pages/Production.tsx`
- `src/ui/pages/Market.tsx`
- `src/ui/pages/Finance.tsx`
- `src/ui/pages/SupplyChain.tsx`
- `src/ui/pages/Retail.tsx`
- `src/ui/pages/News.tsx`
- `src/ui/pages/Settings.tsx`
- `src/ui/pages/CompetitorsAndInvestment.tsx`
- `src/ui/hooks/useMobile.ts`

### Out of Scope

- `DesignSystemShowcase` 之类的开发展示页
- 大规模视觉重设计
- 新增一套独立的移动导航体系
- 改动游戏逻辑、市场逻辑或生产逻辑

## Responsive Strategy

### Breakpoints

保留现有 `useMobile` 断点，并在布局判断中补充“窄桌面”概念：

- `>= 1280px`: 宽桌面，允许主要双栏或三栏布局保留
- `1024px - 1279px`: 窄桌面，固定侧栏默认折叠，详情/队列改覆盖式面板
- `768px - 1023px`: 平板，主内容单栏，次级内容通过抽屉或切换按钮进入
- `< 768px`: 手机，保持单主栏，不允许常驻侧栏

### Global Rules

- 固定宽侧栏在窄桌面及以下不再常驻占位
- 顶部工具栏允许换行，避免按钮被裁切
- 网格列数基于窗口宽度减少，优先保证卡片完整显示
- 右侧详情区改为覆盖层或抽屉，而不是继续压缩主内容
- 浮动面板在小窗口下不再长期悬浮遮挡主区，而是改为按钮唤起
- 所有页面主容器必须允许必要的纵向滚动，不允许因为 `overflow-hidden` 导致内容丢失

## Page Designs

### Production

当前问题最明显：左侧建筑目录、主列表、右侧详情、右下建造队列会在小窗口下互相挤压。

改法：

- 宽桌面保留当前三部分并存模式
- 窄桌面及以下：
  - 左侧 `BuildingCatalog` 默认关闭，通过头部按钮打开
  - 右侧 `BuildingDetailPanel` 不再占固定 `w-80`，改为覆盖式面板
  - `ConstructionQueuePanel` 不再固定悬浮压主区，改为点击按钮后显示覆盖式浮层
  - 建筑网格列数降低，避免卡片被挤窄
- 顶部工具按钮在小窗口下允许换行

### Market

当前问题是左侧商品/筛选区、中央主区、右侧信息区同时存在时容易横向溢出。

改法：

- 宽桌面保留多栏
- 窄桌面及以下：
  - 次级信息栏收起为“详情/分析”按钮入口
  - 图表、供需信息、生产建筑列表改为纵向堆叠
  - 右侧固定信息区变为抽屉或覆盖层
  - 各卡片内部的长标题、数值区增加 `min-w-0` 与换行保护

### SupplyChain

当前左右侧板宽度较大，在小窗口下最容易导致主内容不可见。

改法：

- 窄桌面及以下：
  - 左侧面板默认折叠，仅保留唤起入口
  - 右侧详情区改为覆盖层
  - 中央画布/主规划区优先保留
  - 弹窗与面板宽度使用 `max-w` 和视口百分比，而不是固定宽度

### Dashboard / Finance / Retail / News / Settings / CompetitorsAndInvestment

这些页面主要问题是统计卡片、表格、工具栏和多列信息在窗口缩小时拥挤或被截断。

改法：

- 多列统计区在小窗口下降为单列或双列
- 标题区、筛选区和操作区允许自动换行
- 卡片容器移除不必要的横向挤压，必要时改为纵向堆叠
- 保留已有视觉风格，不额外加入新视觉组件

## Shared Implementation Plan

- 在 `useMobile` 基础上扩充一个“窄桌面”判断，供页面布局统一消费
- 每个重点页面只做最少必要改动，不引入新的全局布局系统
- 对于“详情区 / 队列 / 侧栏”这类次级面板，统一采用按钮唤起的覆盖式容器思路
- 对于“顶部操作区”，统一增加换行与间距自适应

## Testing Strategy

考虑到当前仓库没有完整的 DOM 交互测试依赖，这次以“纯布局决策逻辑测试 + 全量回归验证”为主：

- 为共享布局判断补纯逻辑测试
- 运行 `npx vitest run`
- 运行 `npm run build`

## Risks

- 多页同时改造时，最容易出现的是某些按钮入口仍然保留旧定位，导致覆盖层与主区互相遮挡
- `overflow-hidden` 清理不当可能让某些页面出现双滚动条
- 覆盖式面板如果没有统一关闭入口，会让小窗口下的操作路径变长

## Acceptance Criteria

- 主游戏页面在较小窗口下不再出现“关键 UI 被挤没、看不到、点不到”的情况
- 次级内容都能通过清晰入口访问，而不是被硬裁掉
- 主内容区域始终优先可见
- 全量测试与构建通过
